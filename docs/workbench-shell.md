# 工作台外壳：从「单页应用」到「按场景分工的工作室」

> 本文记录一次**架构移植**：参考 [`luanyujia-workbench`](../../luanyujia-workbench-main/)（一套基于 DSH 的多场景桌面工作台），
> 把它的结构搬到 AgentMatrix-SC 上。代码在 [`agentmatrix-shell/`](../../agentmatrix-shell/)。

## 1. 为什么要搬

原来的 AgentMatrix 是**单页应用**：13 个路由挂在同一个左侧导航下，用户在一个页面里反复跳转。
这在"功能演示"阶段够用，但有三处不顺手：

| 问题 | 具体表现 |
|---|---|
| **切场景要重走导航** | 想看"交付追踪"要依次点 运行监控 → 审计日志，每次都要重新定位 |
| **AI 没有场景感** | 平台里有四条业务链路，但助手不知道你正在看哪条，回答只能泛泛而谈 |
| **交接散在会话里** | "上次做到哪、卡在哪"存在对话历史中，换一次会话就丢 |

源工作台给出的答案是四件事：**场景（一块界面）+ 记忆（文件化交接）+ 会话绑定（AI 认得自己是谁）+ 壳与引擎解耦**。
我们的情况没法照抄"钉 DSH 会话"（那是把内嵌的引擎网页钉住），但另外三件完全适用，而且能做得更硬——
**让助手看到的数字直接来自数据库**，而不是模型自己编。

## 2. 结构：三层，各自只认下一层

```
┌──────────────────────────────────────────────┐
│ 外壳层（agentmatrix-shell/，Electron 或浏览器）    │
│  scenarios/*.json   →  场景 = 网格 + 面板         │
│  memory/*.md        →  场景记忆（§〇 交接 ≤4KB）    │
│  renderer/app.js    →  面板注册表（view/status/memory/chat/links）│
└───────────────┬──────────────────────────────┘
                │ 只通过 HTTP 认识平台，不 require 它的代码
┌───────────────▼──────────────────────────────┐
│ 平台层（apps/api）                              │
│  GET  /workbench/context  → 实时快照（任务/运行/审批/矩阵/策略）│
│  POST /workbench/ask      → 记忆 + 快照 + 问题 → 模型结论      │
└───────────────┬──────────────────────────────┘
                │
┌───────────────▼──────────────────────────────┐
│ 数据层（PostgreSQL）                            │
│  任务 / 运行 / 步骤 / 审批 / 死信 / 审计 / 矩阵数据源 │
└──────────────────────────────────────────────┘
```

关键约束（照源工作台的 L2/L4 分层）：

- **场景配置与场景记忆属于外壳**：它们是文件，平台不落库。壳可以换（Electron ↔ 浏览器），记忆还在。
- **平台只提供能力**：快照与结论都是接口，外壳不直连数据库。
- **面板注册表在外壳**：加一种面板 = 加一个函数，不动主进程、不动后端。

## 3. 与源工作台的逐条对应

| 源工作台 | 本实现 | 差异与理由 |
|---|---|---|
| `scenarios/<id>.json`（id 必须等于文件名） | 同 | 照抄。这条硬规矩能省掉"文件名与 id 不一致"的排查时间 |
| 面板类型注册表（`renderers.js`，24 种） | `PANEL_RENDERERS`（5 种） | 只保留需要的五类；每类都是一个 `(body, panel, ctx) => Promise` |
| `sessionTitle` / `sessionId` / `pinTarget` 钉 DSH 会话 | **不搬**，改为后端 `/workbench/ask` | 我们不需要把"引擎网页"钉进面板：AI 面板直接调平台接口，少一层注入脚本，也少一整类"鬼绑定"问题 |
| 场景私有记忆 `§〇 交接`（≤4KB） | `memory/<场景id>.md`，编辑器带字节计数与红线提示 | 同 |
| 项目记忆（一项目一份 ≤8KB） | 暂未做（项目维度由"工作流 + 运行"承担） | 见 §6 边界 |
| 派单-回执（一次派单 = 一条回执） | 平台侧已有等价物：任务 → 运行 → 步骤证据 + 审计 | 回执的"证据链"本来就在 `run_steps` 与 `audit_logs` 里 |
| Electron 主进程起点、扫目录、发 IPC | `main.js`（约 180 行） | 只做四件事：开窗、扫场景、读写记忆、转发平台接口 |
| 壳与引擎解耦（HTTP + token） | 同 | `shell.config.json` 配账号，主进程登录后把 token 注入 iframe |

## 4. 面板五类

| type | 做什么 | 为什么需要 |
|---|---|---|
| `view` | 用 iframe 嵌已有页面，自动加 `embed=1`（隐藏主站侧栏）并注入登录态 | 复用而不是重写：13 个路由一条都不用改 |
| `status` | 场景快照：待审批 / 24h 成功 / 矩阵覆盖 / 积压，15s 刷新 | 让"这个场景现在什么状态"在一屏内可见 |
| `memory` | 场景记忆编辑器（文件读写 + 4KB 红线） | 交接落在文件里，不随会话消失 |
| `chat` | 场景助手：记忆 + 快照 + 问题 → 结论，可一键写回记忆 | AI 认得自己是哪个场景 |
| `links` | 快捷入口（系统浏览器打开主站页面） | 需要完整交互时跳出面板 |

`embed=1` 是这次唯一改到主站的地方（`apps/web/src/App.tsx` 与 `auth.tsx`）：
- `embed=1` 时不画侧栏与顶栏，只渲染页面内容——否则一个面板里又是一整套导航；
- `?token=` 由外壳注入，写入 localStorage 后立刻从地址栏抹掉。四个面板同源（都是 5173），第一个写入后其余直接复用。

## 5. 验证

| 项 | 命令 | 结果 |
|---|---|---|
| 外壳冒烟（浏览器模式，7 项） | `node tests/e2e/shell.mjs` | 全通过 |
| Electron 起窗与渲染 | 看 `agentmatrix-shell/shell.log` | `renderer ready tabs=4 current=overview panels=4` |
| 场景助手（真实模型） | 冒烟第 6 步 | `deepseek/deepseek-flash · 966 tokens · $0.000485 · 2659ms`，结论引用了真实 run_id 与矩阵缺口 |
| 主站回归 | `node tests/e2e/routes.mjs` | 18 个页面全通过（`embed=1` 未影响原路由） |

外壳冒烟覆盖：场景标签数量、四个面板齐全、iframe 已注入登录态（不出现登录框）、
场景记忆读到文件且带字节计数、切场景后面板与状态栏同步、助手返回结论且带 Token 计量、无前端运行时错误。

## 6. 已知边界

1. **没做"弹出独立窗口"**：源工作台支持把场景弹成单独窗口，本实现单窗口够用；
2. **没做项目记忆**：项目维度目前由"工作流 + 运行记录"承担，若后续一个场景要并行多个项目，再引入 `memory/projects/`；
3. **`shell.config.json` 是明文演示账号**：正式环境应由环境变量注入；
4. **iframe 依赖主站与后端在线**：离线时面板显示错误态（不白屏），KPI 与助手不可用；
5. **Electron 打包未做**：目前是 `npm start` 直接跑，没有 `electron-builder` 产物。

## 7. 复现

```bat
:: 1) 起平台（在 agentmatrix-sc 根目录）
dev up
dev ps

:: 2) 起外壳
cd agentmatrix-shell
start.cmd          :: Electron 模式
start.cmd web      :: 浏览器模式（http://127.0.0.1:4180）

:: 3) 冒烟
cd ..
node tests/e2e/shell.mjs
```
