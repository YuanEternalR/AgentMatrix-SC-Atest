# 场景身份索引

> 场景 id ↔ 面板 id ↔ 用途。修改 `scenarios/*.json` 后需同步本表。
>
> **说明**：模板原本这里还有「会话 id / pinTarget」两列，那是给 `harness`（DSH 引擎会话）用的。
> 现在只有总览的 `ov-chat`（DSH 会话）用 `harness`，它的会话绑定直接写在 `overview.json` 里
> （`sessionTitle: "工作台总览"` + `pinTarget: ["工作台总览"]`），所以这张表不单列那两列；
> 其余场景的 AI 面板仍是原生助手（`am-assistant` → `POST /workbench/ask`），不需要会话绑定。
>
> 现状：**5 个场景 / 21 个面板** = 20 个原生渲染器面板 + 1 个 `harness` 面板（总览的 DSH 会话）。
> 原总览的「DSH 大脑」（`ov-dsh`，`am-dsh`）已于 2026-11-23 按反馈删除；渲染器代码仍注册、暂无场景使用。

## 启动落地

`renderer/customer-start.js` 的 `FIRST` 决定开机进哪个场景（当前 `overview`）。
标签栏最前面固定是「DSH 引擎」（`data-sc-id="harness"`，不可拖），它**保留可见**：引擎由工作台自行拉起、
能获取 token，进入后即真实的 DSH 会话界面。
