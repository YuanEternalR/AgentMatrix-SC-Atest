> 补记（智能体管理，2026-11-23）：
>
> - **在线测试会实际执行一遍**：先逐个执行绑定技能（真实计时），再把输入与技能结果交给模型；
>   轨迹里每一步都有耗时与 Token，模型步还会记录成本。Mock 与真实模型走同一条代码路径。

>   状态没有歧义。
> - **没有做的**：对话式多轮测试（当前是表单式单轮）、工具调用多轮循环（引擎也是单轮）。
>   规格写的是"对话式或表单式"，取后者。

## 六、差距清单与建议

### 建议补（成本低、验收价值高）

| 项 | 工作量 | 理由 |
|---|---|---|
| 密钥管理页 | 1 天 | 目前密钥只走环境变量；有页面更符合"密钥只以名称引用"的完整形态 |

### 建议在论文中说明"不做"（不勉强实现）

| 项 | 说明口径 |
|---|---|
| SQL / MCP 技能 | HTTP 与内置函数已覆盖"外部系统"与"确定性计算"两类，SQL/MCP 属于接入形式差异，不影响调度结论 |
| 对话式多轮测试、工具调用多轮循环 | 引擎当前是单轮（一次技能收集 + 一次模型结论）；多轮会引入循环终止与预算控制的额外语义 |
| 并行/汇聚/子工作流节点 | 单链式 DAG 足以验证调度与恢复；并行会引入并发语义，另行研究 |
| 设置页、多租户、SLA | 平台化功能，与"矩阵调度"研究点无关 |
| 审计里的"改派"与"密钥操作"两类 | 系统没有改派接口、也没做密钥管理，没有对应动作可记；补上这两个功能后按现有 `record()` 加一行即可 |
