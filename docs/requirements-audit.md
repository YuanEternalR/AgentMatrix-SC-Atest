## 五、超出要求的部分

| 订单数据 | 种子 / Mock | 真实 DataCo，65,752 单，SHA256 可追溯 |

| 运行取证 | 未要求 | `scripts/record_runs.py` 自动产出真实运行记录与成本明细 |

## 六、差距清单与建议

### 建议补（成本低、验收价值高）

| 项 | 工作量 | 理由 |
|---|---|---|
| 图表导出 PNG/CSV | 半天 | 验收第 13 条直接相关 |
| 审计日志表 + 中间件 | 1 天 | 验收第 10 条；论文"可追溯"论点的实证 |
| 矩阵补「生产协同」「售后逆向」两行 | 半天 | 与规格行数对齐（会变成 8×4=32 格，覆盖率重算） |
| 智能体/技能列表页（只读） | 1 天 | 补齐 `/agents`、`/skills` 路由 |

### 建议在论文里说明"不做"（而非硬做）

| 项 | 说明口径 |
|---|---|
| HTTP/SQL/MCP 技能、技能管理 UI | 本课题聚焦调度与执行语义，技能接入形式不影响调度结论 |
| 并行/汇聚/子工作流节点 | 单链式 DAG 足以验证调度与恢复；并行会引入并发语义，另行研究 |
| 设置页、多租户、SLA | 平台化功能，与"矩阵调度"研究点无关 |
| 审计日志 | 目前以 `run_steps` + `dispatch_decisions` 承担执行留痕；合规级审计需独立设计 |
