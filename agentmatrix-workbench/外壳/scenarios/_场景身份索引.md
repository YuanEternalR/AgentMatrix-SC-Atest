# 场景身份索引

> 场景 id ↔ 面板 id ↔ 用途。改完 `scenarios/*.json` 记得同步这张表。
>
> **说明**：模板原本这里还有「会话 id / pinTarget」两列，那是给 `harness`（DSH 引擎会话）用的。
> 我们的 AI 面板是原生助手（`am-assistant` → `POST /workbench/ask`），不需要会话绑定，
> 所以这两列在我们的场景里留空。

| 场景 id | 面板 id | 面板标题 | 类型 | 用途 |
|---|---|---|---|---|
| `overview` | `ov-kpi` | 场景快照 | `am-kpi` | 待审批/成功/失败/积压/覆盖率（15 秒刷新） |
| | `ov-approvals` | 待审批 | `am-approvals` | 通过 / 驳回（写操作） |
| | `ov-tasks` | 任务 | `am-tasks` | 状态筛选、看业务参数 |
| | `ov-create` | 新建 | `am-create` | 建任务 / 技能 / 智能体 |
| | `ov-ai` | 场景助手 | `am-assistant` | 真实模型 + 实时快照 |
| `designer` | `ds-canvas` | 设计器 | `am-designer` | 拖节点、改参数、校验、发布新版本 |
| | `ds-ai` | 场景助手 | `am-assistant` | 问流程怎么改 |
| `matrix` | `mx-grid` | 能力矩阵 | `am-matrix` | 8 阶段 × 4 能力的覆盖与缺口 |
| | `mx-agents` | 智能体 | `am-agents` | 在线测试 |
| | `mx-skills` | 技能库 | `am-skills` | 试运行 |
| | `mx-ai` | 场景助手 | `am-assistant` | 问缺口怎么补 |
| `delivery` | `dl-runs` | 运行监控 | `am-runs` | 点行看明细与步骤轨迹 |
| | `dl-chart` | 运行趋势 | `am-chart` | 近 24 小时（原生 SVG） |
| | `dl-dlq` | 死信队列 | `am-deadletters` | 重试 / 忽略 |
| `governance` | `gv-dispatch` | 调度策略 | `am-dispatch` | 改权重 → 试算 → 保存 |
| | `gv-audit` | 审计日志 | `am-audit` | 动作筛选、看变更前后 |
| | `gv-workflows` | 工作流 | `am-workflows` | 校验 |
| | `gv-alerts` | 告警 | `am-alerts` | 确认 / 恢复 |
| | `gv-ai` | 场景助手 | `am-assistant` | 问治理相关的事 |

## 启动落地

`renderer/customer-start.js` 的 `FIRST` 决定开机进哪个场景（当前 `overview`）。
