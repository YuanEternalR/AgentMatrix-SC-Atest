# 场景身份索引

> 场景 id ↔ 面板 id ↔ 用途 ↔ 会话/定位卡/技能。修改 `scenarios/*.json` 或身份卡后需同步本表，
> 再跑 `node 工具\场景记忆.mjs stamp --场景 <场景>` 重盖身份卡（否则 check 报指纹过期）。

> **格式硬约束（工具 `readIdentity` 按 7 列解析，`c.length >= 7`）**：
> 场景 id / 面板 id / 面板标题 / 会话 / 会话 id / 定位卡 / 技能。**不能多列也不能少列**——
> 多一列 `类型` 会把定位卡挤到第 8 列，工具取到 `—`，身份卡指纹就成了空值。
> 面板类型（渲染器）写在标题后的括号里，不进单独列。

> 「会话」「会话 id」是**场景级**绑定：填在每场景**第一行**，指向本场景的 DSH 专属会话
> （工具 `readIdentity` 只按第一行取值，harness 行留 `—` 即可）。2026-11-24 晚起每个场景绑定自己的专属会话：
> 面板一板一分区（`renderers.js` 的 `panelPartition`）＋ 场景 json 写 `sessionTitle` / `sessionId`；
> 场景内不再显示全局会话侧栏（单会话模式），只有「DSH 引擎」页能看到全部会话，跨场景共同修改由它协调。

> 现状：**5 个场景 / 21 个面板** = 16 个原生渲染器面板 + 5 个 `harness` 面板（每个场景一个「DSH 会话」）。
> 2026-11-24：四个场景的「场景助手」（`am-assistant`）已按使用反馈移除，AI 问答统一走 DSH 会话；
> 渲染器 `am-assistant` 仍注册着（要恢复只改 json，不用改代码）。

## 启动落地

`renderer/customer-start.js` 的 `FIRST` 决定开机进哪个场景（当前 `overview`）。
标签栏最前面固定是「DSH 引擎」（`data-sc-id="harness"`，不可拖），它**保留可见**：引擎由工作台自行拉起、
能获取 token，进入后即真实的 DSH 会话界面。
