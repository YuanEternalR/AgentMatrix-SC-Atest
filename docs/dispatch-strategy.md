# 调度策略设计与离线对比

> 本文件对应论文"调度策略"章节的设计与实验部分。
> 结论目前来自**仿真执行器**，不是真实大模型调用，措辞与图表必须如实标注。

## 1. 研究问题

工作台的矩阵里有三层执行者：**大模型智能体**（强推理、贵、慢）、**小模型智能体**（快、便宜、有质量上限）、**内置 skill / 规则引擎**（最快最便宜、能力最窄）。

研究问题：给定一个任务，如何决定交给谁，才能使「成功率 × 成本 × 时延」的组合最优？

这不是单纯的路由问题，因为三个目标互相冲突：把一切交给大模型，成功率最高但成本与时延失控；按成本最低分配，成功率会崩。**本文的假设是：先判断任务复杂度与 SLA 压力，再决定"用大模型还是用小模型/skill"，比任何静态规则都更接近帕累托前沿。**

## 2. 三级决策流程

```
候选池 ──硬过滤──▶ 可行集 ──评分/规划──▶ 决策 ──▶ 可解释拆解（落库，供 UI 与审计）
```

1. **硬过滤**（`filtering.py`）：能力标签不匹配、阶段不符、并发已满、历史 p95 超过 SLA、单步成本超过预算 —— 任一不满足即淘汰，并记录淘汰原因。
   这一层保证"安全"，不允许任何策略越过它（包括大模型规划器）。
2. **评分或规划**：由策略实现。
3. **可解释拆解**：每个因子给出 `raw / weight / contribution`，写入 `dispatch_decisions`，任务详情页据此回答"为什么分给它"。

## 3. 五条策略

| 编号 | 策略 | 分配规则 | 研究角色 |
|---|---|---|---|
| S0 | `s0_all_large` | 全部路由到最大模型智能体（按历史成功率取优） | 质量上限基线 |
| S1 | `s1_fixed_rule` | 硬过滤后按注册顺序取第一个可用 | 下界基线：无反馈、无负载感知 |
| S2 | `s2_weighted` | 能力 35% / 成功率 20% / 负载 15% / 成本 10% / 时延 10% / 亲和 10% | 产品基线策略 |
| S3 | `s3_cost_aware` | 先过质量下限（成功率 ≥ 0.85）与 SLA 保留 20% 余量，再取最低单步成本 | 成本优化上界 |
| S4 | `s4_llm_planner` | 规划模型提出候选 → 规则层校验其必须来自可行集 → 否则回退 S2 | **本文主要创新点** |

S4 的关键设计是**规划器无权绕过硬过滤**：大模型只能"在安全集合里挑"，不能"发明一个智能体"或"忽略 SLA"。这样既保留了 LLM 对复杂语义的判断力，又不会因为幻觉把任务派给不合格的执行者。

## 4. 实验设计

| 项 | 设定 |
|---|---|
| 场景集 | 4 类任务 × N：订单延迟异常（SLA 12s、优先级 1、难度 3–5）、周度补货（SLA 60s、成本敏感、难度 2–3）、供应商风险巡检（SLA 45s、难度 3–4）、运输在途异常（SLA 8s、难度 2–4） |
| 智能体池 | 9 个，覆盖大模型 / 小模型 / 规则引擎三档，同一能力格内存在成本-质量梯度 |
| 控制变量 | 所有策略面对**同一批任务、同一组候选、同一次随机抽样** |
| 指标 | 成功率、P50/P95 时延、单任务成本、未分配数、回退次数、调度耗时 |
| 复现 | `python scripts/evaluate_strategies.py --count-per-type 8` |

**抽样控制**：每个任务的"质量骰子"只由 `task_id` 决定，与选中哪个智能体无关，因此各策略面对相同运气（配对设计，消除策略间方差）；时延抖动按 `(task, agent)` 独立播种，保证完全可复现。

## 5. 结果（仿真，32 个场景）

| 策略 | 成功率 | P50 时延 | P95 时延 | 总成本 | 相对 S0 成本 |
|---|---|---|---|---|---|
| S0 全大模型 | 87.5% | 6254 ms | 10151 ms | $4.81 | 100% |
| S1 固定规则 | 87.5% | 8508 ms | 11995 ms | $3.75 | 78% |
| S2 加权打分 | **68.8%** | 1840 ms | 10151 ms | **$1.44** | **30%** |
| S3 SLA 成本优先 | 84.4% | 8185 ms | 11995 ms | $2.87 | 60% |
| S4 大模型规划 | 84.4% | **2935 ms** | 10151 ms | $3.92 | 82% |

数据源：`docs/experiments/dispatch-comparison.md`（由脚本生成，勿手改）。

### 四条可写进论文的结论

1. **静态加权打分不可用于生产**：S2 把成本压到 30%，代价是成功率从 87.5% 掉到 68.8%（-18.7pp）。原因是权重对任务难度不敏感——高难度异常单被派给了 0.82 成功率的规则引擎。
2. **加一条质量下限就能挽回大半损失**：S3 只多花 2 倍成本（30%→60%），成功率回到 84.4%（-3.1pp）。说明"质量下限"是比"调权重"更有效的控制手段。
3. **大模型规划买到的是时延，不是成功率**：S4 与 S3 成功率同为 84.4%，但 P50 时延低 64%（2935 vs 8185 ms），代价是成本高 37%。**规划器在有 SLA 压力的任务上主动买快线，在宽松任务上降级到小模型**——这正是"大模型规划、小模型执行"的预期形态。
4. **S1 偶然与大模型基线持平，恰恰说明固定规则不可依赖**：它的成功率 87.5% 只是注册顺序恰好偏向强智能体，P95 却最差（11995 ms），换一批智能体就会失效。

## 6. 有效性威胁（答辩会被问，必须先承认）

| 威胁 | 说明 | 应对 |
|---|---|---|
| 执行结果是仿真 | 成功率由 `success_rate × 难度惩罚` 抽样得到，不是真实模型输出 | 产品执行已接 DeepSeek（见 `docs/experiments/real-runs/`），但**策略对比仍用仿真器**以保证控制变量；两者口径不同，论文中分别标注 |
| 种子数据人为构造 | 9 个智能体的成功率/成本是设定值 | 用真实历史 `run_steps` 滚动更新 `success_rate` 与 `avg_cost_usd` |
| 单次运行无置信区间 | 每策略只跑 1 遍场景集 | 增加重复实验（不同任务播种）与 bootstrap 置信区间，报均值 ± 标准差 |
| 场景规模小 | 32 个任务 | 扩展到 200+，并加入难度分布偏斜的敏感性分析 |
| 规划器是启发式替身 | `mock_planner` 用复杂度阈值模拟 LLM 判断 | 论文中明确区分"规划器策略"与"规划器质量"，后者单独评测 |
