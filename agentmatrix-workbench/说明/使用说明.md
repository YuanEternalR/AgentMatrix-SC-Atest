# 使用说明

> 这套工作台改造自 `luanyujia-workbench` 公开模板（MIT），领域换成了**供应链智能体矩阵**。
>
> 干净克隆第一次使用：先按工作台 [`README.md`](../README.md) 的「首次安装」装一次
> （Electron、引擎依赖、DSH 家目录、平台 `.env`；需要 Node.js 24.9+），之后每次启动不用重复安装。

## 启动

```bat
cd agentmatrix-workbench
start.cmd                  :: 起工作台：平台 + DSH 引擎都由它自己拉起来
```

平台（站点 5173 / 接口 8000）不再需要先手动 `dev up`：工作台打开的一瞬，主进程会探一次
`http://127.0.0.1:8000/health`，没起就在仓库根目录跑 `dev.cmd up`（WSL 常驻 + docker compose，
幂等）。启动页会显示「平台启动中… / 平台已就绪」，面板请求会等平台就绪再发，不会先报「加载失败」。

需要手动介入时（在仓库根目录执行）：

```bat
dev up                     :: 手动起平台（幂等，已在跑就秒回）
dev ps                     :: 看容器与常驻会话
dev down                   :: 停平台
```

如需复用已在运行平台、关闭自动启动：设置 `AM_PLATFORM=0` 后运行 `start.cmd`。

新开的 DSH 对话会自动加载仓库根 `AGENTS.md`（开工顺序 → 读 `docs/HANDOFF.md` → 当前基线），
无需每次重新交代项目背景；该文件由引擎 profile 的 `agent-instructions` 加载，
项目状态变更后需同步其「当前基线」。

`start.cmd` 是纯 ASCII 的薄壳，真正的逻辑在 `scripts/launch.cjs`（中文提示在那里输出）。

## 五个场景

| 场景 | 面板 | 干什么 |
|---|---|---|
| **工作台总览** | 6 | 快照 + 待审批（可批可驳）+ 任务列表 + 新建 + 场景助手 + DSH 会话 |
| **工作流设计** | 2 | 拖节点摆位、改参数与连接、校验、发布新版本 |
| **能力矩阵** | 4 | 8 阶段 × 4 能力的覆盖与缺口；智能体在线测试、技能试运行 |
| **交付追踪** | 3 | 运行监控（点行看步骤）、近 24 小时趋势、死信重试/忽略 |
| **治理与策略** | 6 | 调度策略（改权重→试算→保存）、审计日志、工作流校验、告警确认、账号切换、场景助手 |

合计 **21 个面板 = 20 个原生渲染器 + 1 个「DSH 会话」webview**（总览里那个真实 DSH 引擎界面；原「DSH 大脑」面板已按反馈删除）。

## 面板约定

- 除总览的「DSH 会话」外，所有面板都是**原生渲染器**（`renderer/am-panels*.js`），不嵌网页；
- 数据经主进程代理（`window.am.get/post/put`），账号与 token 不进渲染层；
- 面板标题栏右侧有「导出 CSV」（表格类）或「导出 PNG/CSV」（趋势图）；
- 点标题栏 **▲** 展开到整屏高度，`Esc` 收起。

## 未使用的部分（模板自带，与本项目领域无关）

`pc-*`（磁盘清理）、`review-*`（自我复盘）、`bl-*`（Blender）、`site-*`（个人站）等渲染器
仍在 `renderers.js` 里，但没有场景使用；`harness` 只在总览的「DSH 会话」面板里使用（钉
`sessionTitle=工作台总览`）。顶栏的市场/捐赠/网页版 AI 入口由 `renderer/retarget.js` 隐藏。
