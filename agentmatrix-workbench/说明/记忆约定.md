# 记忆约定（1 页）

> 这套工作台的记忆是**文件**，不是聊天记录。每个场景一个文件夹，AI 开场先读它。
> 现有 5 个场景目录：`工作台总览` / `工作流设计` / `能力矩阵` / `交付追踪` / `治理与策略`。
> 判定口径：**工具 `check` 跑得过，才算符合本约定**（2026-11-24 裁定：文档与工具不一致时以工具实测为准，并回写本节）。
> 已知例外：会话绑定一项（场景 json 缺 `sessionId`）仍红，按 §七 待裁，其余项必须全绿。

## 一、放在哪

```
引擎数据\.dsh\场景记忆\
  <场景>\场景私有记忆.md   ← 这个场景的记忆（唯一真源，人写）
  <场景>\身份卡.md         ← 工具写（身份/权限/定位卡指纹）⛔ 手改即校验失败
  <场景>\场景画像.md       ← 工具写（布局/面板/渲染器，从场景 json 推导）
  <场景>\_文件索引.md      ← 这个场景有哪些文件（工具建，可手补）
  <场景>\项目记忆\        ← 每个项目一份
  <场景>\归档\            ← 交接时把旧版挪进来（只进不改）
  _共享记忆\              ← 多个场景都要用的东西
```

定位卡（身份卡指纹的来源）在 `外壳\scenarios\身份卡\<场景id>.md`；改卡或改场景 json 后必须 `stamp`。

## 二、一份私有记忆的格式

- `## §〇 当前交接`：**五小节**，≤4 KB
  1. `### 1) 上次交接` 2. `### 2) 当前项目`（表） 3. `### 3) 私有记忆变更`
  4. `### 4) 下一步 / 卡点` 5. `### 5) 全貌`（工具生成，别手改）
  > 第 5 节是工具硬要求；`记忆约定` 早期版本只写四小节，2026-11-24 已按裁定补齐。
- `## 核心职责`：≥3 条（工具强制，少一条 check 不过）——负责什么 / 不碰什么 / 一句话
- `## §一~§五`：职责边界 / 干活入口 / 坑与决策（**只追加**）

## 三、四条铁律

1. **§〇 ≤4 KB**：只写“下一轮接手要知道的”，细节进 §五 或归档
2. **交接才归档**：`node 工具\场景记忆.mjs 交接 --场景 <名字>` 会把旧版挪进 `归档\`
3. **只追加**：§五 决策与坑只往下写，不改历史
4. **check 未通过时不更换会话**：`node 工具\场景记忆.mjs check --场景 <名字>`

## 四、常用命令

```powershell
node 工具\场景记忆.mjs list                          # 看每个场景缺什么
node 工具\场景记忆.mjs init --场景 工作台总览          # 建骨架 + 身份卡/画像（已存在不覆盖正文）
node 工具\场景记忆.mjs stamp --场景 工作台总览         # 重生成身份卡/画像（改卡或改 json 后必跑）
node 工具\场景记忆.mjs 交接 --场景 工作台总览          # 归档旧版 + 补 §〇
node 工具\场景记忆.mjs check --场景 工作台总览         # 自检（--all 全场景）
```

`--场景` 传目录名（`工作台总览`）或场景 id（`overview`）都行。

**会话列**：`harness` 面板一板一分区（`renderers.js` 的 `panelPartition`），各记各的会话，
`会话 id` 填 `—` 即可；只有**按标题钉会话**时才需要 `sessionId` 做身份核对。

**身份索引 7 列硬约束**：`外壳\scenarios\_场景身份索引.md` 必须是
`场景 id | 面板 id | 面板标题 | 会话 | 会话 id | 定位卡 | 技能` 七列；多一列（例如「类型」）会把定位卡挤错列，
身份卡指纹随即变空、check 报「没有这张场景卡」。面板类型写在标题后的括号里。

## 五、跨场景

`node 工具\发消息.mjs --to 交付追踪 "请查看这个产物"` —— 纯文件，不发网络请求。对方下一轮读自己的 §〇-通知 就能看到。

## 六、与仓库文档的分工（双轨，2026-11-24 裁定）

| 层 | 文件 | 管什么 |
|---|---|---|
| 项目级 | 仓库根 `docs/HANDOFF.md` + `AGENTS.md` | 平台/接口/数据基线、测试、编码纪律、安装与启动 |
| 场景级 | 本节这套场景记忆 | 该场景的面板、交互、数据口径、场景内坑与决策 |

两边各留一行指针，**不互相复制正文**；同一件事只在属主层写，另一层只写“见某处”。

## 七、冲突与压缩（裁判权）

1. **准则互斥 → 交用户裁决**（哪条保留、哪条让路），不自行改判、不在文档里写两套并存的说法；
2. **工具与文字不符**：以工具 `check` 的实测为准，当场回写本节，并把改动写进对应场景 §五；
3. **可压缩**：§〇 只留接手要点，长内容进 §五/归档/项目记忆；同一句话只写一处；文档每次只改必要段落。
